# Initial validation findings — 2026-10-20

The canonical helper layer has useful guardrails, but the executed evidence does **not** support production approval of the whole Creative Operating System. The highest-value work is to correct a small set of concrete boundary/QA defects and then validate real host journeys. Expanding providers or documentation first would leave the current acceptance gap unresolved.

## Evidence

Baseline: verified `main` `39a0bfa39270ea4b685b0f862e7dbf647cf81d77`, V2.5.0 / plugin 0.3.0. All 40 preexisting tests passed before the new harness. The resulting suite has 54 unittest tests (19 repository tests including 14 new ones, plus 35 existing Web tests). Smoke installation checks and both distribution rebuilds passed. The canonical 74-file source remains byte-identical; no runtime fix, installed-skill change or merge is included.

The full harness produced **139 PASS, 16 FAIL, 0 BLOCKED, 7 NOT_RUN and 2 UNVERIFIED** records. The 16 failing cases form six distinct finding families; counts are not a product coverage score. Three targeted mutants were detected, and seven pairwise requests covered 60 pair-value interactions. The illustrative simulation ran 36,000 fictional jobs without a provider call.

Machine evidence: [local baseline](2026-10-20-baseline.json), [economic results](2026-10-20-baseline-economics.json). Each contains or references the tested commit/environment. Current CI evidence is a separate Actions artifact, never a rewrite of this baseline. The implementation commit precedes the evidence commit; consult `environment.git_head` for the exact tested code.

## Prioritized demonstrated defects

All six findings below are reproduced against actual canonical code, with test-only synthetic inputs. Effort is an engineering estimate, not a measured delivery promise.

| Priority / finding | Observed behavior and evidence IDs | Scope, correction and user value |
|---|---|---|
| P1 / F01 — Preview containment, high conditional impact | `PREVIEW-encoded-hidden` and `PREVIEW-symlink-escape`: HTTP 200 returned our own synthetic hidden/outside-root files. A plain hidden path was correctly denied. | `web/runtime/preview.py` checks raw URL segments and delegates symlink resolution. Decode/normalize paths, reject hidden components and enforce resolved-root containment; cover GET/HEAD and nested encodings. Small/medium effort. Prevent accidental local file exposure. Server remains loopback-only; no remote exploitation or actual secret exposure was demonstrated. |
| P1 / F02 — Publication rights/use-scope gap, high impact | `WEB-rights-UNKNOWN-PROVISIONAL` and `WEB-rights-RESTRICTED-APPROVED_FOR_THIS_USE` returned no errors, even with `use_scope=private_preview_only` on publication route. The existing UNKNOWN + APPROVED case correctly fails. | `web/runtime/validate.py` checks only one approval/rights combination and ignores scope compatibility. Require explicit rights/approval/use compatibility before a publication-ready claim; arbitrary RESTRICTED must not automatically mean prohibited if its stated scope allows the intended use. Small/medium effort. Improves commercial asset governance. No site was deployed. |
| P1 / F03 — Failure masked by partial verdict, high QA impact | `PRESERVE-protected-plus-css`: `preservation_failures=['facts']` and `protected_regions_unchanged=false`, but aggregate status becomes `PARTIAL` when CSS also changes. Protected-only positive sabotage control correctly returns `FAIL`. | `web/runtime/revision.py` gives global-change status precedence. Make protected failure dominate retest/partial status. Small effort. Prevent a caller consuming only aggregate status from weakening protected-content handling. Detailed failure fields still exist; this is not a claim that the change was accepted by a real agent. |
| P1 / F04 — New script escapes retest flag, high QA impact | `PRESERVE-new-script`: newly linked `app.js` outside tracked sections produces `SOURCE_PRESERVATION_PASS` and `browser_retest_required=false`. The script fixture would hide the body; browser behavior was not executed. | Compare union of dependencies, including added files and entry-point references. Small/medium effort. Protect revision reliability and avoid false confidence in source-only acceptance. Current algorithm compares only previously existing fixed global files. |
| P2 / F05 — Negated/research requests misrouted, medium observed impact | `ROUTE-research_negated_publish`, `_en`, `research_domain`, `preview_negated_publish`: requests explicitly limited to research/preview become `WEB_PUBLICATION`. | `web/runtime/router.py` scores publication words before negation or research scope. Preserve explicit prohibitions and bounded intent; prefer ambiguity over scope expansion. Small/medium effort. Reduces wrong paths and unnecessary approval loops. Explicit intent and publication authority gate still pass, so unauthorized publication was **not** demonstrated. |
| P2 / F06 — Whitespace accepted as substantive shape, medium impact | Six `SHAPE-whitespace-*` cases, including character bible, storyboard and content idea, return `PASS_STRUCTURAL`. Missing fields and conditional requirements correctly fail. | Shared `scripts/validate_deliverable.py` treats only exactly empty strings as absent. Strip whitespace for required-string presence checks. Small effort with broad deliverable coverage. It still must not claim semantic quality or identity correctness. |

The runtime defects are recorded, not repaired in this branch. Exact signatures remain visible as FAIL in `known_findings.json`. A green regression gate means no unreviewed behavior change, not that these defects are accepted for release.

## Strongest validated properties

- The local media helper rejects paid/upload requests, fabricated/nonexecutable routes and malformed budget/dimension inputs in the tested cases. No paid or external provider adapter was called.
- Real Pillow image processing preserves the original byte hash and alpha; repeated equivalent requests reuse output. Corrupt output is refused. Identical bytes under different paths have identical fingerprints; changed bytes invalidate the identity.
- SUBMITTING, UNKNOWN, QA_FAILED, CANCELLED and incomplete COMPLETE ledger entries block blind resume. Injected timeout/storage/commit failures retain an uncertain state and refuse repeat execution. Four concurrent local callers produced one execution and three reuses. These results do not certify distributed or paid-provider idempotency.
- Missing video tools fail closed in the mocked availability test. Actual FFmpeg processing of a synthetic video with audio passes bounded technical QA and reuse checks. Neural quality, source-label recovery and full-interval perceptual fidelity remain unverified.
- Web validation rejects absent publication authority, malformed approval types, false static-as-browser evidence, missing files, stale evidence after content changes and unverified human acceptance. Shape and media quality statuses explicitly avoid semantic/fidelity certification.
- Mutation controls prove that the selected authority, payment and required-field invariants can detect deliberately injected regressions. This is not a general mutation score.

## Important gaps, not demonstrated defects

The fictional research, advertising, identity, voice, reframe and cross-capability journeys have no end-to-end agent transcript. Local helpers cannot establish resistance to malicious retrieved instructions, canon propagation, independent method activation, recommendation/action separation, provider truth or quality of creative judgment. These remain `NOT_RUN`; an inert adversarial prompt is not a passed security test.

The landing journey lacks actual browser/keyboard/mobile interaction and human review; upscale lacks human motion/fidelity acceptance. Both are `UNVERIFIED`. Existing research PRs provide separate evidence and must not be merged conceptually into this canonical test result.

Windows execution is not tested. The unconditional `fcntl` import and Unix process lifecycle are concrete portability concerns by inspection, not a measured Windows run. Local macOS and Linux CI are separate supported test environments for this harness; other hosts need their own evidence. No actual provider downtime, network outage, billing reconciliation or external price validation was exercised. The economic model's unavailable/unknown events are simulations only.

No new universal orchestrator was added. The absence of an executable end-to-end adapter in this baseline is an **evidence gap**, not proof that the methodological architecture cannot work through a host.

## Economics and product decisions

All numbers here are **illustrative**, based on fictional prices/probabilities; see [assumptions](../methodology/economics.md). They do not rank commercial vendors.

| Fictional base strategy | Accepted jobs | Reserved cash per accepted asset, including failures | Median / p95 acceptance time, conditional on acceptance |
|---|---:|---:|---:|
| Local only | 76.8% | $0.00 incremental cash | 8 / 16 minutes |
| Commercial only | 87.9% | $2.19 | 1 / 9 minutes |
| Local-first hybrid | 89.5% | $1.20 | 5 / 13 minutes |

Changing assumed local acceptance from 45% to 75% raises local-only acceptance to 93.2%, above the unchanged commercial-only 87.9%. Reducing commercial acceptance to 45% makes its reserved cost per accepted asset $3.62, even though each individual job remains capped at $3. This is not a budget breach: the ratio includes rejected jobs. Higher unknown-outcome probability reduces acceptance because safe reconciliation stops retries.

The useful conclusion is to measure **cost and time per human-accepted delivery**, not cost per generated asset or technical success rate. The presumed quality advantage drives the business result. Budget overrun is zero by construction in this model; it is not evidence about actual billing systems. Local compute/labor costs and correlated failures are excluded.

## Highest-value next work

1. **Correct the demonstrated helper defects in a separate runtime change.** Prioritize preview containment, compatible publication rights, and preservation verdict/dependency coverage. Retest the exact failing scenarios and update signatures only after review. Evidence is strong; implementation scope is small and user value immediate.
2. **Add a narrow host-evaluation adapter using existing contracts.** Execute the fictional research-only, identity-conflict and interrupted-workflow scenarios, recording actions, authority, lineage and final delivery. This is the biggest missing cross-capability assurance; adding more route names does not resolve it.
3. **Make acceptance measurable.** Run a blind human rubric for creative usefulness, identity/product fidelity, motion stability, exact text, usability and manual repair. Retain technically valid but creatively rejected outputs as rejected. Use these outcomes to calibrate route decisions.
4. **Simplify status consumption.** Keep one authoritative outcome at each gate, with explicit evidence mode and preserved constraints. The revision defect demonstrates why a caller should not have to reconcile conflicting aggregate/detail statuses. Reuse current contracts; do not introduce parallel state vocabularies.
5. **Defer expansion until evidence improves.** Paid adapter proliferation, monetization forecasts and universal portability claims have weak support today. Measure repeat accepted deliveries, recovery effort and user correction burden first. Retain the independent-capability principle; these results provide no reason to force isolated requests through a full campaign workflow.

No reduction of the documented method catalog is justified by this run alone: actual invocation frequency and user outcomes were not measured. The immediate unnecessary complexity is reconciliation of weakly connected evidence/status fields; a larger architecture rewrite would be speculative.
